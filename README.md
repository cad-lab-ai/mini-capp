# mini CAPP — демонстрационная САПР ТП для AI-агентов

**mini CAPP показывает предприятиям принцип работы агента-технолога:** агент изучает
каталог производства, составляет техпроцесс, проверяет ссылки на оборудование и оснастку
и формирует маршрутную карту. Паспорт производства можно наполнять и редактировать по разделам.

Это демонстрационный стенд для знакомства с подходом и обсуждения задач заказчика.
Следующий шаг — **персональное внедрение на предприятии**: подключаем ваши CAD/САПР ТП,
PDM/PLM/ERP, справочники оборудования, формы документов и правила согласования под
конкретные процессы и доступные интерфейсы. Состав интеграции определяем после обследования;
перечисленные подключения не входят в готовые возможности демоверсии.

**Хотите увидеть этот сценарий на своей детали и оборудовании?**
[Обсудить демонстрацию и персональное внедрение с cad-lab](https://cad-lab.xyz/).

Публичный репозиторий: [GitHub](https://github.com/cad-lab-ai/mini-capp).

Локальный MCP-сервис хранит каталог производства и
структурированные техпроцессы, проверяет ссылки на ресурсы и строит обзорную HTML-карту.
Работает без КОМПАСа, ERP, облака и встроенной LLM. CAD-агент передаёт сведения о детали самостоятельно.

## Установка из каталога cad-lab

В «Маркетплейсе» откройте «Плагины», выберите категорию CAD и карточку **mini CAPP**.
Плагин из [plugin/](plugin/) подключает 12 инструментов к агенту и запускает локальный MCP-сервис на
машине выполнения чата. Нужны Git и uv в PATH; Python и зависимости подготавливает uv.
Рабочие данные находятся в каталоге данных плагина и сохраняются между чатами на этой машине.
Начните с `workspace_initialize`, затем наполните каталог вашего демонстрационного производства.
Каталог общий для этого экземпляра плагина на машине; изоляции по предприятиям/чатам пока нет.

## Запуск

Нужны Git в PATH, Python >=3.11 и uv. Проверено на Windows с Python 3.14.

```powershell
uv sync --frozen
$env:MINI_CAPP_WORKSPACE = 'D:\cad-data\factory-01'
uv run --frozen mini-capp
```

Прежние команда `process-planning` и переменная `PROCESS_PLANNING_WORKSPACE`
поддерживаются для существующих настроек. В контейнере cad-lab папка сабмодуля
называется `process-planning`.

Сервис использует транспорт MCP stdio через [Python SDK v1](https://py.sdk.modelcontextprotocol.io/v1/).
Процесс ожидает MCP-клиента; в stdout нет интерактивного CLI.
Без переменной окружения данные находятся в `~/.cad-lab/process-planning`.
Рабочая Git-ревизия и стартовые разделы появляются после `workspace_initialize`. До этого обращение к сервису может создать пустую папку для блокировки.

Пример настройки клиента (замените абсолютные пути):

```json
{
  "mcpServers": {
    "mini-capp": {
      "command": "uv",
      "args": ["run", "--frozen", "--directory", "<путь к клону mini-capp>", "mini-capp"],
      "env": {"MINI_CAPP_WORKSPACE": "<путь к отдельной папке данных>"}
    }
  }
}
```
