# Разработка и публикация

## Архитектура

[models.py](../src/process_planning/models.py) — строгие схемы; [store.py](../src/process_planning/store.py) — каталог, ревизии, блокировка и атомарные пакеты;
[planning.py](../src/process_planning/planning.py) — проверки и представление; [server.py](../src/process_planning/server.py) — MCP-адаптер.

Из рецепта cad-lab сохранены постоянные ID, разделение чтения/записи,
один канал изменений, этап с откатом, история, проверка влияния и честное `unknown`.
Здесь нет родного API CAD: изменяющий канал — декларативный пакет операций с каталогом,
без исполнения Python-кода агента. GUI-плагин и CAD-транзакции для автономного сервиса неприменимы.

## Проверки

Из корня репозитория выполните:

```powershell
uv run --frozen pytest -q
```

Тесты покрывают переносы разделов, сохранение ID и снимков, конфликт ревизий,
откат пакета, запрет выхода за корень, неподтверждённые ресурсы, HTML-экранирование
и реальную MCP stdio-сессию с проверкой аннотаций и ошибок.

## Сборка плагина

Адаптер содержит сгенерированную копию Python-сервиса и схем инструментов. Для обновления выполните из корня репозитория:

```powershell
uv run --frozen python tools/package_plugin.py
uv run --frozen pytest -q
cd plugin
npm ci --ignore-scripts
npm run typecheck
npm test
```

## Публикация и зеркало

GitLab — источник изменений. После успешных Python- и Node-проверок GitLab CI
публикует `main` и теги в GitHub; расхождение истории приводит к ошибке вместо
принудительной перезаписи. `GITHUB_MIRROR_TOKEN` хранится защищённой маскированной
переменной CI и передаётся Git HTTP-заголовком, не в URL remote.
Секреты, локальные рабочие каталоги и демонстрационные данные не входят в репозиторий.
