# Каталог, техпроцессы и MCP

## Паспорт — каталог

```text
workspace/                       # отдельная папка данных, не репозиторий исходников
├── .git/                        # история и неизменяемые ревизии данных
├── factory/
│   ├── general/
│   ├── equipment/
│   │   └── turning/
│   │       └── LATHE-001.json
│   ├── workplaces/
│   ├── tooling/
│   ├── materials/
│   ├── capabilities/
│   ├── quality/
│   └── subcontractors/
└── processes/
    └── PART-001.json
```

Агент просматривает каталог по уровням, ищет записи в разделе и читает отдельные карточки.
Можно создавать подразделы, редактировать карточки, переносить файлы и целые разделы,
удалять отдельные записи и пустые разделы. ID ресурса не зависит от пути и не меняется при переносе.
Иерархия разделов свободная; `kind` определяет тип карточки независимо от её размещения.

Каждая карточка содержит источник, дату наблюдения, подтверждённость сведений,
доступность и произвольные характеристики. Для численных характеристик указывайте единицы
в `properties`, например `{"max_diameter": {"value": 250, "unit": "mm"}}`.
Сервис проверяет структуру карточки, но не интерпретирует произвольные характеристики станков.

## Инструменты

| Инструмент | Назначение |
|---|---|
| `workspace_initialize` | Создать пустой каталог со стартовыми разделами |
| `tool_contract` | JSON Schema карточки/техпроцесса, грамматика изменений и ограничения |
| `catalog_list` | Дочерние записи каталога; пагинация, выбор ревизии |
| `find` | Рекурсивный текстовый поиск в выбранном разделе; компактные карточки |
| `inspect` | Прочитать одну карточку или техпроцесс |
| `change_apply` | Атомарный пакет правок с ожидаемой ревизией |
| `history` | История версий |
| `impact` | Какие текущие техпроцессы ссылаются на ресурс |
| `validate` | Проверить структуру и ресурсы по закреплённой версии паспорта |
| `route_preview` | Получить HTML обзорной маршрутной карты без записи на диск |
| `template_get` | Прочитать действующий шаблон, ревизию и доступные подстановки |
| `template_edit` | Изменить HTML/CSS-шаблон для своего рабочего каталога с историей и контролем ревизии |

`catalog_list` и `find`: `limit` от 1 до 100, `offset`, `next_offset`, `truncated`.
`inspect`: одна запись до 64 КБ. Поиск пока сканирует каталог без индекса.
`impact` и проверки предназначены для небольшого локального каталога: выдача зависимостей
пока без пагинации. Это ограничение MVP, не готовое решение для крупных заводских баз.

## Изменения

`workspace_initialize` создаёт Git-историю, признак каталога сервиса и стартовые разделы в пустой папке. Повторный вызов возвращает текущую ревизию. Другие операции могут создать пустую папку для файла блокировки, но рабочей ревизии до инициализации в ней нет.

Сначала `workspace_initialize`, затем `tool_contract` и чтение нужного раздела.
Ревизия из ответа чтения передаётся в `expected_revision`:

```json
{
  "expected_revision": "<40-символьный hash из ответа сервиса>",
  "label": "Уточнить характеристики токарного станка",
  "changes": [
    {"op": "mkdir", "path": "factory/equipment/turning"},
    {
      "op": "put",
      "path": "factory/equipment/turning/LATHE-001.json",
      "record": {
        "id": "LATHE-001",
        "name": "Пример записи; заменить фактическими данными",
        "kind": "equipment",
        "availability": "unknown",
        "properties": {},
        "evidence": {
          "source": "Описание от владельца; требуется уточнение",
          "observed_at": "2026-11-24",
          "status": "unknown"
        }
      }
    }
  ]
}
```

`put` заменяет **одну запись целиком**. Перед редактированием прочитайте её через `inspect`:
опущенные необязательные поля получают значения по умолчанию, а не сохраняют прежние.
`move`: `{"op":"move","path":"factory/equipment/turning","destination":"factory/equipment/lathes"}`.
`delete`: `{"op":"delete","path":"factory/equipment/lathes/LATHE-001.json"}`.
До изменения или удаления ресурса вызовите `impact`.

Пакет до 100 изменений — один Git-коммит. Ошибка откатывает весь пакет.
Конфликт `expected_revision` требует перечитать данные и согласовать собственную правку с новой версией.
Для восстановления отдельной карточки прочитайте её старую ревизию и запишите новым пакетом.
История не переписывается; отдельного инструмента полного undo пока нет.

Каталог данных принадлежит сервису. Внешние редакторы одновременно с MCP не поддерживаются:
незакоммиченные правки блокируют запись через сервис. Lock-файл защищает от параллельных запросов;
после аварийного завершения оператор должен проверить отсутствие работающего процесса перед
ручным удалением `.planning.lock`. Сбои процесса/питания посреди записи требуют восстановления
рабочего дерева по последнему Git-коммиту. Гарантия отката относится к обработанным исключениям,
не к аварийному отключению питания. Нужны обычные резервные копии.

## Техпроцессы и проверки

Схема: ID, имя, ревизия детали, источник КД, материал, заготовка, `passport_revision`,
допущения, нерешённые вопросы, операции. Операция: ID, имя, ID ресурсов,
установы, переходы, контроль, время в минутах и основание времени.

Техпроцесс закрепляет Git-ревизию каталога. Новая редакция паспорта не меняет старые процессы.
Для актуализации агент явно обновляет `passport_revision` и запускает `validate`.
Ревизия общая для workspace: изменения техпроцессов тоже создают новые коммиты;
это допустимые снимки состояния паспорта, а не независимая нумерация паспортов.

Перед коммитом `change_apply` проверяет схемы, уникальность ID в пределах каждого каталога записей, уникальность ID операций в техпроцессе и наличие закреплённой ревизии паспорта.

`validate` читает выбранный техпроцесс, проверяет его схему и закреплённую ревизию, наличие ресурсов, их доступность и подтверждённость, источник указанного времени и открытые вопросы. Проверка опирается на уникальность, обеспеченную при записи.
Отсутствие ресурса — `fail`; неподтверждённость или отсутствие сведений — `unknown`.
`structural_status=pass` **не означает** пригодность технологии: `engineering_status`
всегда `unknown`. Совместимость оборудования, режимы, допуски и нормативы пока не рассчитываются.

Единственный статус техпроцесса в MVP — `draft`. Утверждение, роли, подписи,
сертифицированные формы ЕСТД, PDF/DOCX и интеграция с CAD не реализованы.
Печатная карта оформлена как технический бланк: рамка, реквизиты, таблица операций,
поля подписей. Шаблон расположен отдельно в [route.html](../src/process_planning/templates/route.html).
Допущения, вопросы и результаты проверок остаются в модели/ответе `validation`,
но не печатаются на карте. Ревизии сохраняются в HTML-метаданных.
Внешнее сходство бланка не означает соответствия унифицированной форме ЕСТД.

### Настройка шаблона через MCP

1. Вызвать `template_get`: получить HTML действующего шаблона и `revision`.
2. Изменить оформление, шрифты, рамку, название организации или расположение граф.
3. Передать весь HTML в `template_edit(expected_revision, html, label)`.
4. Вызвать `route_preview` для проверки результата.

Подстановки: `$name`, `$designation`, `$material`, `$blank`, `$rows`, `$revision`,
`$passport_revision`. Обязательна только `$rows` — строки операций; они содержат шесть
ячеек: номер, название, ресурсы, установы/переходы, контроль, время. Заголовки таблицы
должны соответствовать этим ячейкам. Изменение состава ячеек пока требует правки рендерера.
Для буквального знака доллара использовать `$$`. Неизвестная подстановка, некорректный
синтаксис и размер больше 64 КБ отклоняются до записи. Это проверка контракта подстановок,
не HTML/CSS-валидатор и не автоматическая проверка качества вёрстки.

Шаблон сохраняется в **каталоге данных** `templates/route.html`, отдельно от паспорта
и исходников сервиса. Один шаблон на workspace. Редактирование создаёт отдельную
Git-ревизию и не меняет карточки ресурсов или техпроцессы. До первой настройки используется
встроенный шаблон пакета. Для восстановления прежнего оформления прочитать
`template_get(revision="<предыдущий commit>")` и сохранить полученный HTML новым
вызовом `template_edit` с текущей `expected_revision`.

`route_preview(revision=...)` использует пользовательский шаблон из указанной ревизии;
если его там ещё не было — встроенный из установленной версии пакета.
Встроенный шаблон может меняться при обновлении пакета; для полного закрепления оформления
сохранить его в workspace через `template_edit`. Обычный `change_apply` шаблоны не редактирует.

Учебные примеры cad-lab должны использовать паспорт «СеверНефтеОснастки» из
справочника учебного производства cad-lab. Паспорт нужно перенести в каталог
явно через инструменты сервиса.
Тесты используют явно синтетические ресурсы и не являются производственными маршрутами. Границы первоначальной проверки описаны в [отчёте первого среза](reports/first-slice-2026-11-24.md).
